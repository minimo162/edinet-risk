# Microsoft 365 Copilot 用プロンプト（統合1本）

> 推奨運用は `docs/easiest-path.md`。**利用者は M365 Copilot Chat に下の1本を貼って送るだけ。** SharePoint は開かない。成果物は **Excel（.xlsx）1冊**（6シート固定: 対象確認 / 変化表 / 差分詳細 / 分析 / マツダ比較 / 要確認）。チャットは短い要約＋ファイル案内のみ。Excel が作れないときだけ Word（.docx）にフォールバック。

## 利用者の手順（3ステップ）
1. 共有 Teams チャネルにピン留めされた「EDINET リスク分析プロンプト」を全文コピーする（管理者がリンク入りで投稿済み）。
2. M365 Copilot Chat を開く（Teams 左側の「Copilot」か、ブラウザの microsoft365.com のチャット）。
3. 貼り付けて送信する。社を指定したいときだけ、1行目の `対象:` に証券コードか社名を書く（最大10社。空欄なら `社一覧.xlsx` の区分=ピアの社＝マツダ同業ピア）。

キーも Python も不要。SharePoint のフォルダを開く必要もない（ファイルはプロンプト内のリンクから Copilot が読む）。

## 統合プロンプト（この1本を配布する）

管理者は `<<…>>`（6か所: 差分・監視・社一覧・社別本文・週次要約・見本ブック）を公開先の実リンクに差し替えてから配布する。各リンクの行の括弧内が、そのリンク先のファイル名（取り違えの確認に使う）。利用者は差し替え済みの文面をそのまま貼る。

```
対象: （空欄ならマツダ同業ピア。指定する場合は証券コードか社名を最大10社、読点区切り）
【対象の決め方】「対象:」が空欄なら、社一覧.xlsx の「区分」が「ピア」の社すべてを対象にする（区分=依頼 の社は含めない）。指定があれば、社一覧.xlsx の証券コードか社名に一致する社を区分を問わず対象にし、見つからない社は「対象外」とする。

あなたは有価証券報告書「事業等のリスク」の前期→当期比較を手伝います。根拠は次のファイルだけです（edinet-risk の週次出力）。
- 差分（risk_diff.xlsx）: <<risk_diff.xlsx のリンク>>
- 監視（monitor.xlsx）: <<monitor.xlsx のリンク>>
- 社一覧（社一覧.xlsx）: <<社一覧.xlsx のリンク>>
- 社別本文（社別フォルダの md）: <<社別フォルダのリンク>>（必要な社の md だけ参照。社一覧.xlsx にある社の md だけを使い、社一覧にない社の md は古いものなので使わない）
- 週次要約（週次要約.md）: <<週次要約.md のリンク>>（xlsx を読めないときの代替）
リンクから開けない場合は、同じ公開フォルダ内の最新の risk_diff.xlsx と社別 md（xlsx も読めなければ 週次要約.md）を使ってください。
リンク先のファイル名が括弧内の名前と違うとき、同じリンクが2か所以上にあるとき、「<<」「>>」が残っているときは、そのリンクを使わず、同じ公開フォルダ内の括弧内の名前のファイルを使い、`要確認` に「リンク誤り（ファイル名）」を1行出す。

必ず **ダウンロード可能な成果物ファイル** を作ってください（チャット本文の表だけは不可）。作り方（使うツール・ライブラリ）は問わない。

【体裁（毎回同じにする・最重要）】
見本ブック（yoY_report_template.xlsx）: <<yoY_report_template.xlsx のリンク>>（公開フォルダの templates/ または同階層）
- 見本を開き、シート構成・列名・色・フォント・見出し行の行高・ウィンドウ枠固定・オートフィルタを**そのまま踏襲**して実データで埋める。見本のサンプル行はすべて実データに置き換える（残さない）。
- 見本を開けないときは、この【体裁】の指定だけで作り、チャット本文に「見本未参照」と書く。
- ファイル名: `事業等のリスク_YoY_YYYYMMDD.xlsx`（日付は実行日）。
- シート順・名前は固定: `使い方` は成果物に含めない。含めるのは `対象確認` → `変化表` → `差分詳細` → `分析` → `マツダ比較` → `要確認` の6枚だけ。
- 色（見本と同じHEX）:
  - ネイビー #1B3A4B … 変化表ヘッダ／タイトル文字
  - ティール #2A9D8F … 対象確認・マツダ比較ヘッダ／アクセントバー
  - コーラル #E76F51 … 要確認ヘッダ
  - 琥珀薄 #FBF3DC … 文字数増減率 +10%以上、注目度「中」
  - コーラル薄 #FDEDE9 … 状態「対象外」、増減率 −10%以下、注目度「高」
  - ティール薄 #E8F6F3 … 状態「対象」、注目度「低」
  - 交互行 #F4F7F8、グリッド #D0D7DE
- フォント: 游ゴシック（なければ Yu Gothic UI / Meiryo UI）。タイトル18pt太字、ヘッダ11pt白文字中央・行高28、本文10pt・折り返し。データ行の行高は固定せず、折り返した全文が見える高さにする（見本どおりにするのは見出し行だけ）。
- 数値: 文字数増減率はパーセント表示（0.0%）。**再計算しない**。週次要約.md「2. 変化表」の「文字数増減率」をそのまま転記する（risk_diff.xlsx にはこの列がない）。週次要約.md が読めない、または値が「-」なら空欄にする。

【根拠ファイルの列（これ以外の列・値を作らない）】
- risk_diff.xlsx `概要` シート: 会社, シート, 当期docID, 前期docID, フラグ, 当期項目, 前期項目, 一致, 修正, 改題, 移動, 統合, 分割, 新設, 削除, 要確認, 変更あり, 軽微, 変更なし
- risk_diff.xlsx 社別シート（`概要` の「シート」列の名前）: #, ラベル, 変更, 要確認, 前期の項目, 前期の本文（青字＝前期のみ）, 当期の項目, 当期の本文（赤字下線＝当期のみ）, 続き（1項目が複数行に分かれるときは、ラベルのある行から次のラベルの行の手前までが1項目）
- 社別/*.md: 「### n. [ラベル・変更X・要確認] 見出し」の下に「前期 N 字 → 当期 M 字」と 前期／当期 の本文（原文のまま）
- 週次要約.md「2. 変化表」: 新設, 削除, 変更あり, 軽微, 変更なし, 要確認, 前期文字数, 当期文字数, 文字数増減率
- 社一覧.xlsx: 証券コード, 社名, 区分(ピア/依頼), EDINETコード, 当期書類, 当期期末, 前期書類, 前期期末, 基準日T, 更新日
- monitor.xlsx `監視_詳細` シート: 区分, 指標, entity_id, 証券コード, 会社名, cur/prev, docID, 値, 閾値, 詳細（この「区分」は監視の分類で、社一覧の区分とは別。社との突き合わせは証券コード（4桁、社一覧と同じ）で行う。証券コードが空の行は全体の指標なので `要確認` には社名なしで出す）
- 上にない値（ページ番号、文字数増減率の自前計算など）は作らない。該当列は空欄にする。

【本文の読み方（社別 md）】
- 1項目は「### n. [ラベル・変更X(・要確認)] 見出し」の行から、次の「### 」の行の手前まで。最後の項目は、単独の「---」行の手前まで。
- 本文は「#### 前期」「#### 当期」の下の、「> 」で始まる行だけ。「（なし）」はその側に本文が無いという意味。段落は「> 」で始まる1行（「>」だけの行は段落の区切りで、数えない）。
- 単独の「---」行より後ろの「- 出典:」「- 利用条件:」「- 加工した旨:」「- 加工者:」「- 注意:」は注記で、本文ではない。変更前・変更後・要約・分析に入れない。週次要約.md の最後の単独の「---」行より後ろも同じ注記。

【変更種別の対応（CLI の8分類 → 追加/削除/改訂）】
| CLI のラベル | 変更 | 変更種別 |
|---|---|---|
| 新設 | （問わない） | 追加 |
| 削除 | （問わない） | 削除 |
| 修正・改題・統合・分割 | （問わない） | 改訂 |
| 一致・移動 | あり・軽微 | 改訂 |
| 一致・移動 | なし | 載せない（数えない） |
| 上のどれにも当てはまらない／ラベルが読めない | — | 差分詳細に載せず `要確認` へ（理由「分類不明」） |
- 「要確認」が付いた項目は上の対応で差分詳細に載せたうえで、`要確認` シートにも1行出す（フラグ「対応付け要確認」）。
- 変化表の 追加テーマ数／削除テーマ数／改訂テーマ数 は、この対応で数えた差分詳細の**項目数**（社ごと）。行数ではない（ページ/位置の値が同じ行は1件と数える）。

【各シートの列（見本どおり・列を足したり減らしたりしない）】
1. `対象確認`: 証券コード, 社名, 状態(対象/対象外), 当期書類, 当期期末, 前期書類, 更新日, メモ
   - メモには社一覧.xlsx の区分と基準日T を「区分=ピア／基準日T=YYYY-MM-DD」の形で必ず書く（基準日T がファイル間で違えば `要確認` にも出す）。
2. `変化表`（サマリ）: 会社名, 証券コード, 追加テーマ数, 削除テーマ数, 改訂テーマ数, 文字数増減率, 代表的な変化（1行）, 根拠ファイル
   - 比較なし（前期なし等）の社は数を空欄にし、`要確認` に理由を出す。
   - 代表的な変化は、並び順の先頭ではなく次の順で選ぶ: 追加 → 削除 → 改訂のうち変更が「あり」の項目。同じ順位の中では、社別 md の「前期 N 字 → 当期 M 字」の差が大きい項目。変更が「軽微」の項目は選ばない（軽微しかない社は「軽微な変更のみ」と書く）。
3. `差分詳細`（必須・読者向け）: 会社名, 証券コード, 項目見出し, 変更種別(追加/削除/改訂), 変更前（前期の文言）, 変更後（当期の文言）, 何が変わったか（要約）, 根拠ファイル, ページ/位置
   - 変更種別は上の対応表で決める。ページ/位置は risk_diff.xlsx の社別シート名と項目番号（例「マツダ #3」）。ページ番号は根拠ファイルにないので書かない。
   - テーマ名だけで終わらせない。改訂は変更前・変更後に**本文全文**。追加は変更前「（なし）」、削除は変更後「（なし）」。
   - 変更前・変更後のどちらかに段落が2つ以上ある項目は、段落ごとに Excel の行を分ける（n 行目に変更前の n 番目の段落と変更後の n 番目の段落。段落が足りない側は空欄）。2行目以降も、会社名・証券コード・項目見出し・変更種別・根拠ファイル・ページ/位置は1行目と同じ値を入れる。何が変わったか（要約）は1行目だけに書く。
   - 何が変わったか（要約）の書き方:
     - 変更前と変更後を文単位で突き合わせ、「当期で消えた記述」「当期で増えた記述」「言い換え・数値の変更」を分けて書く。
     - 消えた記述だけの項目は「〜の記述を削除」と書く。「表現を更新」「記述を更新」とまとめない。
     - 変更種別が追加なら「当期に新設」、削除なら「当期で削除」で始める。
     - 要約に書く語句は、同じ項目の変更前か変更後に実際にあるものだけ。
4. `分析`（必須）: 種別(注目点/示唆/注意), 内容, 対象社, 根拠（差分詳細の項目見出し）, 確度(事実/推測), 優先度(高/中/低)
   - 差分詳細を読んだうえでの読み取り。根拠見出しを必ず紐づける。断定できないことは確度「推測」。最大8行程度。
5. `マツダ比較`: 区分(共通/マツダ固有/他社のみ), 内容, 関係する社, 注目度(高/中/低), 根拠（差分詳細の項目見出し）, 根拠ファイル
   - `分析`・`マツダ比較` の書き方:
     - ある記述が「追加された」と書けるのは、変更前に無く変更後に有るときだけ。「削除された」はその逆。変更前・変更後の両方に有る記述は増減ではないので挙げない。
     - 「対象社」「関係する社」には、差分詳細の変更前・変更後を両方読んで、その増減を確かめた社だけを書く。
     - 区分「共通」は、関係する社のすべてで同じ向きの増減を確かめたときだけ。マツダだけ向きが違う（他社が残した記述をマツダが削除した、など）なら「マツダ固有」に書く。
6. `要確認`: 証券コード, 社名, フラグ, 理由（人が確認すること）, 根拠ファイル, 優先度(高/中/低) ※該当なしなら1行目に「該当なし」
   - 出すもの（2種類）:
     - 項目単位（1項目1行）: 「要確認」が付いた項目（フラグ「対応付け要確認」）、対応表で「分類不明」の項目。理由の先頭に「社別シート名 #番号 項目見出し」を書く。
     - 社単位（1社1フラグ1行）: monitor.xlsx `監視_詳細` の行、週次要約.md「3. 要確認リスト」の理由のうち「突合」「前期なし」「フラグ」「比較なし」、社一覧で対象外の社、基準日T の不一致、リンク誤り。
   - 週次要約.md「3. 要確認リスト」の「対応付けの要確認 n 件」は、項目単位の行と同じものなので行にしない。
   - 証券コード・フラグ・項目見出しが同じ行は1行にまとめる。要確認件数は、まとめた後の行数。

Excel をどうしても作れない場合のみ、同じ6節（対象確認・変化表・差分詳細・分析・マツダ比較・要確認）・同じ見出し順の Word（.docx）。色は見出しをネイビー／ティール／コーラルで区別。HTML/PDF は作らない。

チャット本文は短く: (1) ファイル名 (2) 対象社数と更新日 (3) 要確認件数（`要確認` シートの行数） (4) 見本を開けなかったときは「見本未参照」。表はファイル側のみ。

【出力前の点検】作った後に次を確かめ、合わなければ直してから出す。
- `変化表` の追加・削除・改訂テーマ数が、`差分詳細` のその社の項目数（ページ/位置の種類の数）と合う。
- 変更前・変更後・要約に、注記（「出典:」「利用条件:」「加工した旨:」「加工者:」「注意:」）の文が入っていない。
- 変更種別が追加の項目の変更前は「（なし）」、削除の項目の変更後は「（なし）」。
- `要確認` に同じ項目・同じフラグの行が2つ無い。
- `分析`・`マツダ比較` の各行に書いた社が、差分詳細の該当行の変更前・変更後で確かめられる。

ルール: 根拠ファイルにない情報は書かない。推測は「推測」と明記。代替ファイルでも開けない場合はチャットに理由を書いて止まり、空の成果物は作らない。体裁が見本と違う場合は作り直す。
```

## 回答がおかしいときの対処（利用者向け）
- 「ファイルを開けない」と返る → リンク先の閲覧権限がない可能性。共有 Teams チャネルで管理者に連絡する（SharePoint を自分で探しに行く必要はない）。
- 「対象外」の社が出た → そのまま共有 Teams チャネルに証券コードを書いて依頼する。次回バッチで追加される。
- 回答が途中で切れた → 同じチャットで「続けて」と送る。

## 管理者の準備
- 対象: 指定社（最大10）／指定なしはマツダ同業ピア（`config/transport7.toml`）。
- 管理用 Windows で取得〜monitor を実行し、`publish_peer.ps1` で CLI 出力を正規名（`risk_diff.xlsx`・`monitor.xlsx`・`社一覧.xlsx`・社別本文 md・`週次要約.md`）にリネームして SharePoint の公開フォルダへ置く（同期できない環境では管理者が「置き換え」で手動アップロード。`admin-runbook.md` §12。**正規名は固定**。CLI の出力名は `risk_diff_transport7.xlsx` 等で異なるので、手で置くときもリネームする。名前が変わるとプロンプトのリンクが切れる）。正規名とリネーム表は `docs/publish_peer.spec.md`。
- 利用者グループに公開フォルダの **閲覧権限** を付ける（Copilot は利用者本人の権限でしか読めない）。利用者に SharePoint を開かせる運用にはしない。
- 公開フォルダに `docs/templates/yoY_report_template.xlsx` を置き、統合プロンプトの見本リンクを差し替える。
- 統合プロンプトの `<<…>>` を実リンクに差し替え、共有 Teams チャネルにピン留め投稿する。プロンプトを変えたら投稿を差し替え、古い文面は残さない。
- 配布前の確認（差し替え漏れ・取り違えの防止）: 差し替えた文面で `のリンク>>` を検索して 0 件であること（差し替え前は6件。プロンプト本文の「「<<」「>>」が残っているときは…」の説明文は差し替えの対象ではないので残る）。各リンクを開き、行の括弧内のファイル名と一致すること（特に「監視（monitor.xlsx）」が `monitor.xlsx` を指し、`週次要約.md` と同じリンクになっていないこと、「見本ブック」が `templates/yoY_report_template.xlsx` を指していること）。同じリンクが2か所にないこと。
- **API キーは管理用 Windows の `EDINET_API_KEY` か `paths.api_key_file` のみ。** 公開フォルダ・プロンプト・チャットに含めない。

## パイロット第1確認（未確認・配布前に必ず実施）
リンクを貼るだけで M365 Copilot がファイルを読めるかは、まだ実機で確かめていない。利用者に配る前に、閲覧権限だけを持つ利用者アカウントで次を確認する。

- [ ] 統合プロンプトを貼ると、成果物の `対象確認` シートに各社の更新日が出る（＝リンク先を開けている）
- [ ] `変化表` の文字数増減率が `週次要約.md` の値と一致し、追加／削除／改訂の数が対応表どおり（risk_diff.xlsx の新設・削除の数と一致）
- [ ] `差分詳細` の本文が社別 md と一致する（追加・削除リスクの文言をそのまま引用）
- [ ] `monitor.xlsx` の要確認フラグが `要確認` シートに反映される
- [ ] 成果物が6シート（対象確認 / 変化表 / 差分詳細 / 分析 / マツダ比較 / 要確認）で、見出し行にオートフィルタが付いている
- [ ] 社を `対象:` に指定しても、10社以内なら途中で切れない
- [ ] 管理者が次の週のファイルを「置き換え」でアップロードした後も、同じ統合プロンプト（同じリンク）のまま新しい更新日が読める（`対象確認` の更新日・基準日T が新しい週のもの。手動アップロードの手順は `admin-runbook.md` §12）

失敗したときのフォールバック（上から順に試す）:
1. xlsx が読めない → 管理者が週次で `週次要約.md` も置く（`publish_peer.spec.md` §1）。統合プロンプトは要約 md＋社別 md だけでも6シートが成立する（数値は要約 md の値を引用し、ラベルは社別 md の見出しの [ ] から読む）。
2. リンク自体が効かない → プロンプトの「同じ公開フォルダ内の最新ファイルを使う」指示で足りるかを見る。足りなければ、利用者が Copilot Chat の入力欄で「/」を押して `risk_diff.xlsx`・`週次要約.md` を名前で選ぶ手順を runbook に足す（SharePoint の画面は開かない）。
3. それでも不可 → 案2（Copilot Studio エージェント、ナレッジ＝公開フォルダ）へ切り替える（`easiest-path.md` §1）。

## 成果物の体裁（固定）
見本: `docs/templates/yoY_report_template.xlsx`（6シート＋`使い方`、各シートの見出し行にオートフィルタ付き）。色・列・フォント・見出し行の行高は見本が正（データ行の行高は固定せず、折り返した全文が見える高さにする。見本のサンプル行の行高は踏襲しない）。Copilot には「見本どおり」と指示し、列の追加・削除や色の独自変更を禁止する。パイロットでは見本と成果物のヘッダ色・列順が一致するかを確認する。
