目的

有価証券報告書「事業等のリスク」が前期から当期でどう変わったかを、 社内の誰でも M365 Copilot Chat に統合プロンプト1本を貼るだけ で読めるようにする。 1回の回答で変化表・マツダ比較・要確認リストがまとめて返る。

利用者の操作（これだけ）

コピー
共有 Teams チャネルのピン留め投稿「EDINET リスク分析プロンプト」
→
2
貼って送信
M365 Copilot Chat（Teams の Copilot か microsoft365.com）。社を指定するときだけ1行目に書く
→
3
読む
変化表・マツダ比較・要確認リスト（対象外の社は冒頭に表示）

SharePoint は管理者が結果ファイルを置く裏側の置き場。利用者は開かない（Copilot がプロンプト内のリンクから読む）。設計上の想定で、公開フォルダとピン留め投稿は未作成。

  • 対象は利用者が指定する社（最大10社）。指定がなければマツダ同業ピア（config/transport7.toml）。
  • プライム全社の抽出はバッチ専用（チャットでは扱わない）。

制約（守ること）

社内 PC は Windows のみ

利用者も管理者も Windows。「開発環境」は社外、「隔離実行環境」は M365 Copilot 側の機能で、どちらも社内の機械ではない。

APIキーの渡し方は2つだけ

EDINET_API_KEY か paths.api_key_file。

設定ファイル・プロンプト・チャット・SharePoint・Teams・Git に置かない

製品は Microsoft 365 Copilot

GitHub Copilot ではない。Copilot は EDINET に届かないので、取得は必ず管理用 Windows のバッチ。

次の MVP（この順番で）

  1. publish_peer.ps1 を作り、社内 Windows で動かす
  2. タスクスケジューラ＋SharePoint 同期で週次公開
  3. 統合プロンプトに実リンクを入れ、共有 Teams チャネルにピン留め
  4. docs/admin-runbook.md・キー配置手順・離任前チェックリスト
  5. 非エンジニア1名でパイロットし、つまずきを反映（最初に「リンクだけで Copilot が読めるか」を確認: copilot-runbook.md「パイロット第1確認」）
  6. （任意）Copilot Studio エージェント化

決めること

管理用 Windows の機械 ／ SharePoint の場所と利用者グループの閲覧権限 ／ 更新頻度 ／ 依頼窓口（Teams かフォームか）／ Studio 化の有無
